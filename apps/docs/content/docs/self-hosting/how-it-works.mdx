Happier is three pieces, and its shape follows from where the work happens:
**on your machine, not on a server**.

- **The CLI and its daemon** run on a computer you control. This is where your
  coding agent actually executes, with your repository and the agent's own
  credentials.
- **The relay** stores encrypted payloads and the sync metadata needed to route
  them. It does not run agents, and under the default storage policy it cannot
  read their content.
- **The clients** — mobile, web and desktop — are how you watch and steer.

Sessions sync through the relay so a phone and a laptop see the same
conversation. That is the relay's whole job: moving ciphertext between your
devices and the machine doing the work.

## What travels over the socket

This matters more than it sounds, because it is the part people get wrong when
putting a reverse proxy in front of a self-hosted relay.

**The WebSocket is the primary data path, in both directions.** It is not a
notification channel that tells clients to go fetch something over HTTP.

- **Downstream**, `new-message` carries the whole message —
  `{ id, seq, content, … }` — not a "something changed" ping.
- **Upstream**, clients write over the same socket: `message`,
  `update-metadata` and `update-state` are all client-to-server events.

In **0.3 development**, downstream message events distinguish complete content from
compact hints. A device consuming a Session's transcript, Voice or content pane
receives complete messages and live stream segments. An idle device receives
message identity, sequence, timestamps and attention facts; opening the Session
uses the existing HTTP catch-up path. A mounted SCM view can receive committed
content from its project without receiving hidden live streams. Each API replica
checks current access before selecting either delivery form.

This replaces the 0.3 wire behavior across all components together; mixed 0.2/0.3
components are unsupported. It does not change the stored format or prevent
0.2-created Sessions from opening after upgrade. These are development contracts,
not a stable or preview availability claim.

Writes use optimistic concurrency. Versioned fields — metadata, agent state,
artifact parts, access keys, KV — carry an `expectedVersion`, and a stale write
comes back as `version-mismatch` with the current version attached rather than
silently overwriting. Conflict resolution stays with the client, which is what
lets two devices work on the same session without a lock.

HTTP handles what a long-lived socket is bad at: bulk catch-up after a
disconnect, and transfers that do not belong in a message stream.

<Callout type="warn">
  Self-hosting: size your reverse proxy for a long-lived, chatty WebSocket
  rather than request/response traffic. The most common self-hosting failure is
  an idle timeout shorter than the server's own heartbeat, which silently drops
  machines offline. [Environment variables](/self-hosting/env) has the exact
  figure.
</Callout>

## Reconnecting

Clients are expected to lose the socket and recover: reconnect, fetch what they
missed, reconcile deterministically. A device asleep for a day should end up in
the same state as one that stayed connected, which is why messages carry a
monotonic `seq` rather than relying on arrival order.

## Multiple relay replicas (0.3 development)

A single API process can keep Socket.IO rooms in memory. If a development Home
runs more than one API replica, configure `HAPPIER_SOCKET_ADAPTER=redis-streams`
and `REDIS_URL` for every replica. The current 0.3 source uses the Redis Streams
adapter for ordinary room broadcasts and Redis Pub/Sub for cross-replica socket
discovery and request/acknowledgement traffic.

That shared transport is required for live Session viewers and typing, remote
permission or policy eviction, RPC, and tunnel routing to agree across replicas.
Presence itself is not persisted in Redis: a disconnect, restart, or unavailable
backplane makes current viewer evidence unknown until connected clients declare
their visible Sessions again.

The Redis adapter upgrade and two-node recovery/ACL gates described here are
development deployment requirements, not stable or preview availability claims.
Use [Environment variables](/self-hosting/env) for configuration, and do not mix
old and new adapter generations in one serving cluster.

## Where the encryption sits

Content is encrypted on your device before it reaches the relay, and the keys
stay with your account rather than the server. What that guarantees — and the
storage policies under which it does not — is covered in
[Security](/security) and the [Encryption model](/security/encryption).
